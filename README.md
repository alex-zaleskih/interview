# Shop Cabinet — личный кабинет покупателя

Небольшое приложение: личный кабинет интернет-магазина. Пользователь входит по email и видит свой профиль и список своих заказов.

**Стек:** Go, [gin](https://github.com/gin-gonic/gin), MongoDB ([официальный драйвер v2](https://github.com/mongodb/mongo-go-driver)).
Фронтенд — статический HTML + vanilla JS (ES-модули), без сборки.

## Быстрый старт

Нужны:

- Go 1.25+ (Go 1.21+ сам скачает нужную версию toolchain при первой сборке)
- Docker с Compose v2
- make (необязательно — команды из `Makefile` можно запускать вручную)

```bash
make mongo-up   # поднять MongoDB в Docker; при первом запуске загружаются тестовые данные
make run        # запустить сервер
```

Откройте http://localhost:8080 и войдите под одним из демо-аккаунтов (пароль не нужен):

| Email                | Что внутри                  |
|----------------------|-----------------------------|
| `ivan@example.com`   | 23 заказа, несколько страниц |
| `maria@example.com`  | 6 заказов                   |
| `alexey@example.com` | заказов нет                 |

Фронтенд читается с диска при каждом запросе: после правок в `web/` достаточно обновить страницу.
После правок в Go-коде сервер нужно перезапустить.

## Команды

| Команда            | Что делает                                                 |
|--------------------|------------------------------------------------------------|
| `make mongo-up`    | Запустить MongoDB                                          |
| `make mongo-down`  | Остановить MongoDB (данные сохраняются)                    |
| `make mongo-reset` | Удалить данные и поднять MongoDB заново с тестовыми данными |
| `make seed`        | Перезалить тестовые данные в запущенную MongoDB            |
| `make run`         | Запустить сервер                                           |
| `make test`        | Запустить тесты                                            |
| `make build`       | Собрать бинарник в `bin/server`                            |

## Конфигурация

Через переменные окружения:

| Переменная       | По умолчанию                | Описание                              |
|------------------|-----------------------------|---------------------------------------|
| `HTTP_ADDR`      | `:8080`                     | Адрес HTTP-сервера                    |
| `MONGO_URI`      | `mongodb://localhost:27017` | Строка подключения к MongoDB          |
| `MONGO_DB`       | `shop`                      | Имя базы данных                       |
| `SESSION_SECRET` | `dev-secret-change-me`      | Ключ подписи сессионной cookie        |
| `WEB_DIR`        | `web`                       | Каталог с фронтендом                  |

Если порт 27017 или 8080 занят:

```bash
MONGO_PORT=27018 make mongo-up
MONGO_URI=mongodb://localhost:27018 HTTP_ADDR=:8081 make run
```

## Структура проекта

```
cmd/server/            точка входа, сборка зависимостей, graceful shutdown
internal/
  config/              настройки из переменных окружения
  model/               доменные модели (без привязки к MongoDB)
  repository/          работа с MongoDB: документы, запросы, маппинг в модели
  service/             бизнес-логика
  handler/             HTTP-слой на gin: роутинг, middleware, DTO ответов
  auth/                подписанные сессионные токены
web/
  index.html           личный кабинет
  login.html           страница входа
  static/js/           api.js — обёртка над fetch, dom.js / format.js — хелперы, app.js — логика кабинета
  static/css/
deploy/mongo/init/     скрипт с тестовыми данными (выполняется при первом старте контейнера)
```

Зависимости направлены внутрь: `handler → service → repository`. Интерфейсы объявлены на стороне потребителя
(`handler` описывает, что ему нужно от сервисов, `service` — от репозиториев), поэтому слои легко тестировать с фейками.

## API

Все эндпоинты, кроме входа и выхода, требуют сессионную cookie, которую выставляет `POST /api/auth/login`.
Ошибки возвращаются в формате `{"error": "описание"}`.

| Метод  | Путь               | Описание                                                    |
|--------|--------------------|-------------------------------------------------------------|
| `POST` | `/api/auth/login`  | Вход: `{"email": "ivan@example.com"}` → профиль + cookie    |
| `POST` | `/api/auth/logout` | Выход                                                       |
| `GET`  | `/api/me`          | Профиль текущего пользователя                               |
| `GET`  | `/api/orders`      | Заказы текущего пользователя, новые сверху. Параметры: `page` (с 1), `limit` (по умолчанию 10, максимум 50) |
| `GET`  | `/healthz`         | Проверка работоспособности                                  |

Пример ответа `GET /api/orders?page=1&limit=1`:

```json
{
  "items": [
    {
      "id": "6ac7661c0000000000000001",
      "number": "ORD-2026-01192",
      "status": "new",
      "created_at": "2026-10-08T09:45:00Z",
      "items_count": 1,
      "total": { "amount": 318000, "currency": "RUB" }
    }
  ],
  "total": 23,
  "page": 1,
  "limit": 1
}
```

Суммы передаются в минимальных единицах валюты (копейках): `{"amount": 318000, "currency": "RUB"}` — это 3 180 ₽.

Статусы заказа: `new`, `paid`, `shipped`, `delivered`, `cancelled`.

## Данные

База `shop`, коллекции `users` и `orders`. Тестовые данные генерирует скрипт
[`deploy/mongo/init/01-seed.js`](deploy/mongo/init/01-seed.js) — детерминированно, поэтому ID и содержимое
одинаковые при каждом запуске.

Посмотреть данные вручную:

```bash
docker compose exec mongo mongosh shop
```

## Тесты

```bash
make test
```

Тесты HTTP-слоя (`internal/handler`) и сервисов (`internal/service`) работают с фейками и не требуют запущенной MongoDB.
